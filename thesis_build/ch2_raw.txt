2.1 坐标系与姿态表示
===[293|学位论文正文]===
无人机自主探索涉及多个坐标系。本文使用世界系、机体系和传感器系三类坐标。世界系采用ENU约定，x轴指向东、y轴指向北、z轴指向天；机体系采用FLU约定，x轴指向机头、y轴指向左侧、z轴指向上方。PX4内部使用NED/FRD约定，x轴指向北、y轴指向东、z轴指向下，机体系x轴向前、y轴向右、z轴向下。两套约定之间的转换必须在外部视觉接口处显式完成，否则会出现位置或姿态符号错误。
===[294|学位论文正文]===
设世界系为{W}，机体系为{B}，则机体系到世界系的刚体变换可表示为
===[295|Normal]===
	TWB = [ RWB   pWB ; 0  1 ]	(2-1)
===[296|学位论文正文]===
式中：R_WB为3×3旋转矩阵，p_WB为机体系原点在世界系中的位置。旋转矩阵满足正交约束R^T R = I，行列式为1。对于绕z轴的偏航角ψ，旋转矩阵为
===[297|Normal]===
	Rz(ψ) = [ cosψ  -sinψ  0 ; sinψ  cosψ  0 ; 0  0  1 ]	(2-2)
===[298|学位论文正文]===
四元数q = [w, x, y, z]^T是姿态的紧凑表示，其与旋转矩阵的关系为
===[299|Normal]===
	R(q) = [ 1-2(y^2+z^2)  2(xy-wz)  2(xz+wy) ; 2(xy+wz)  1-2(x^2+z^2)  2(yz-wx) ; 2(xz-wy)  2(yz+wx)  1-2(x^2+y^2) ]	(2-3)
===[300|学位论文正文]===
在本文系统中，camera_init为FAST-LIO初始化时的IMU位姿所对应的地图系，body为IMU系，base_link为PX4机体系，livox_link为雷达射线原点。由于仿真中IMU与base_link原点重合，body与base_link之间为单位变换；livox_link相对base_link的平移为(0, 0, 0.315) m，无旋转。
===[301|学位论文正文]===
PX4外部视觉接口要求输入NED坐标系下的位置与FRD机体系下的姿态。设ENU位置为p_e = (x_e, y_e, z_e)，NED位置为p_n = (x_n, y_n, z_n)，则二者满足
===[302|Normal]===
	pn = [ ye  xe  -ze ]^T	(2-4)
===[303|学位论文正文]===
姿态转换同理。若ENU/FLU下的偏航角为ψ_e，则NED/FRD下的偏航角为ψ_n = π/2 - ψ_e。本文在fastlio_odom_bridge中完成上述转换，并在offboard_control中按同一约定生成位置和偏航设定点。
===[304|Heading 2]===
2.2 激光雷达惯性里程计
===[305|学位论文正文]===
FAST-LIO2采用紧耦合迭代误差状态卡尔曼滤波（iterated error-state Kalman filter，iESKF）融合IMU和激光点云。系统状态包括位置、速度、姿态、IMU零偏和重力向量等。IMU测量用于状态传播，激光点云用于量测更新。与松耦合方法相比，紧耦合方法能够在点云特征较少时仍利用IMU信息维持状态估计。
===[306|学位论文正文]===
设IMU角速度和加速度分别为ω_m和a_m，考虑零偏b_g、b_a和噪声n_g、n_a，则
===[307|Normal]===
	ω = ωm - bg - ng,   a = am - ba - na	(2-5)
===[308|学位论文正文]===
在dt时间间隔内，位置、速度和姿态的连续时间运动学为
===[309|Normal]===
	pdot = v,   vdot = R(a) + g,   Rdot = R[ω]×	(2-6)
===[310|学位论文正文]===
式中：[ω]_×为角速度的反对称矩阵，g为重力向量。对式（2-6）进行离散积分，可得到IMU预积分量。预积分将相邻两帧之间的IMU测量累积为相对运动约束，避免在优化中重复积分。
===[311|学位论文正文]===
设第k帧到第k+1帧的预积分位置、速度和旋转分别为Δp、Δv、ΔR，则状态预测可写为
===[312|Normal]===
	pk+1 = pk + vk Δt + 0.5 g Δt^2 + Rk Δp	(2-7)
===[313|Normal]===
	vk+1 = vk + g Δt + Rk Δv	(2-8)
===[314|Normal]===
	Rk+1 = Rk ΔR	(2-9)
===[315|学位论文正文]===
激光量测采用点到面残差。对于当前帧中的点p_i，将其投影到地图中，找到最近的平面，残差为
===[316|Normal]===
	ri = ni^T (R pi + t - qi)	(2-10)
===[317|学位论文正文]===
式中：n_i为平面法向量，q_i为平面上的一点，R和t为待估计的位姿。将残差对所有点求和，得到非线性最小二乘问题
===[318|Normal]===
	minδx Σ || ri(x ⊞ δx) ||^2Σ_i + || δx ||^2P^{-1}	(2-11)
===[319|学位论文正文]===
其中⊞表示流形上的加法，Σ_i为量测协方差，P为先验协方差。FAST-LIO2采用迭代卡尔曼滤波求解式（2-11），并在每次迭代中更新状态和协方差。与批优化相比，滤波方法计算量稳定，适合在线运行。
===[320|学位论文正文]===
FAST-LIO2的另一个关键组件是增量式kd-tree（ikd-tree）。传统kd-tree在每次地图更新后需要重建，计算开销大；ikd-tree只更新发生变化的局部区域，支持增量插入和删除，从而保证高频率建图。本文使用FAST-LIO2输出的/cloud_registered和/Odometry作为建图与规划的输入。
===[321|Heading 2]===
2.3 三维占据栅格地图
===[322|学位论文正文]===
OctoMap将三维空间递归划分为八叉树节点，每个节点存储该体素的占据概率。设某体素在时刻t的占据概率为P(n|z_{1:t})，采用对数几率表示
===[323|Normal]===
	L(n|z1:t) = L(n|z1:t-1) + L(n|zt)	(2-12)
===[324|学位论文正文]===
其中L(n) = log[P(n)/(1-P(n))]。当射线穿过体素时，占据概率降低；当射线命中体素时，占据概率升高。为了限制观测噪声的影响，通常对单次更新的对数几率进行截断，并设置概率上下限。
===[325|学位论文正文]===
OctoMap将体素分为未知、自由和占据三种状态。未知表示尚未被任何射线确认；自由表示射线穿过且未命中；占据表示射线命中或概率超过阈值。设占据阈值为p_occ，自由阈值为p_free，则状态判别为
===[326|Normal]===
	state(n) = occupied,  P(n) ≥ pocc ; free,  P(n) ≤ pfree ; unknown,  otherwise	(2-13)
===[327|学位论文正文]===
本文使用的OctoMap分辨率为0.15 m，最大传感器距离为70 m。地图以camera_init为固定坐标系，/cloud_registered作为输入点云，/octomap_binary以约10 Hz发布。探索器通过地图查询接口获取体素状态、两点间可见性和机体包围盒的占据情况。
===[328|学位论文正文]===
与纯占据栅格相比，OctoMap的八叉树结构在稀疏场景中具有更高的存储效率；其不足是查询粒度受分辨率限制，薄障碍物可能被漏检。本文在碰撞检查中采用机体包围盒与占据叶子的精确相交判断，以降低离散化误差。
===[329|Heading 2]===
2.4 NBVP探索框架
===[330|学位论文正文]===
NBVP（Next-Best-View Planner）将探索问题转化为局部视点选择问题。算法在当前位姿周围的工作空间内构建RRT，以候选节点可见的未知体素数量作为增益，选择增益最大的枝，并执行其第一段。执行完成后，以新的位姿为根重新构建树，形成滚动时域规划。
===[331|学位论文正文]===
设当前位姿为x_0，工作空间为W，RRT的节点集合为V，边集合为E。采样点x_rand在W内均匀采样，找到树上距离最近的节点x_near，并沿x_rand - x_near方向延伸，得到新节点x_new
===[332|Normal]===
	xnew = xnear + min(||xrand - xnear||, η) · (xrand - xnear)/||xrand - xnear||	(2-14)
===[333|学位论文正文]===
式中：η为单边最大长度。新节点需要满足碰撞约束，即从x_near到x_new的机体包围盒扫掠区域不与占据体素相交。若满足，则将x_new加入树，并计算其增益。
===[334|学位论文正文]===
增益由候选节点的视场和可见性决定。设节点x的视场为F(x)，地图中的未知体素集合为U，则增益可写为
===[335|Normal]===
	G(x) = Σv ∈ V(x) w(v) · I(v ∈ U)	(2-15)
===[336|学位论文正文]===
式中：V(x)为从x可见的体素集合，w(v)为体素权重，I(·)为指示函数。实际实现中，增益还考虑距离衰减和路径代价，常用形式为
===[337|Normal]===
	G(x) = Gunknown(x) · exp(-λ · d(x0, x))	(2-16)
===[338|学位论文正文]===
其中λ为衰减系数，d(x_0, x)为从根节点到候选节点的距离。衰减的作用是抑制过远的候选点，使规划更倾向于近处的高信息区域。
===[339|学位论文正文]===
可见性判断通常沿射线进行。若从x到体素v的射线在到达v之前被占据体素遮挡，则v不可见。对于相机模型，还需判断v是否落在视场角内。对于360°激光雷达，水平方向无遮挡，竖直方向存在有限视场，因此需要根据仰角判断。本文第四章将给出具体的视场模型。
===[340|学位论文正文]===
在树构建完成后，选择增益最大的节点x_best，并沿父指针回溯得到从根到x_best的路径。算法只执行路径的第一段，然后重新规划。这种“只走一步”的策略使系统能够及时响应新观测，但也对执行层的稳定性和目标推进速度提出了要求。若第一段过长或目标推进过快，位置控制器可能出现超调甚至振荡。
===[341|Heading 3]===
2.1.1 旋转的数值稳定性
===[342|学位论文正文]===
旋转矩阵和四元数是两种常用的姿态表示。旋转矩阵直观、便于坐标变换，但存在正交约束，数值积分后需要重新正交化；四元数紧凑、无奇异，但存在双覆盖问题，即q和-q表示同一姿态。在滤波和优化中，通常采用误差状态表示，将姿态误差定义在切空间上，避免直接对四元数做线性插值。
===[343|学位论文正文]===
设当前姿态四元数为q，误差旋转向量为δθ，则更新后的姿态可写为
===[344|Normal]===
	q⁺ = q ⊗ exp(0.5 δθ)	(2-17)
===[345|学位论文正文]===
式中：⊗表示四元数乘法，exp(·)表示四元数指数映射。该更新方式保证姿态始终位于单位球面上，避免因数值积分导致的范数漂移。对于小角度误差，exp(0.5δθ)可近似为[1, 0.5δθ]^T。
===[346|学位论文正文]===
在本文系统中，FAST-LIO内部使用误差状态滤波，PX4使用四元数表示姿态，ROS TF使用四元数。三者之间的转换必须保持符号一致。若在转换中忽略q与-q的等价性，可能出现姿态突然翻转180°的现象。本文在fastlio_odom_bridge中对四元数做归一化和符号检查，保证发送给PX4的姿态与LIO姿态连续。

2.2.1 状态量与协方差
===[351|学位论文正文]===
FAST-LIO2的状态向量通常包括位置p、速度v、姿态R、IMU零偏b_g和b_a、重力向量g等。设状态维度为n，协方差矩阵P为n×n对称正定矩阵。IMU传播时，协方差按
===[352|Normal]===
	Pk+1 = Fk Pk Fk^T + Qk	(2-18)
===[353|学位论文正文]===
更新，其中F_k为状态转移雅可比，Q_k为过程噪声协方差。激光量测更新时，协方差按
===[354|Normal]===
	Pk+1 = (I - K H) Pk	(2-19)
===[355|学位论文正文]===
更新，其中H为量测雅可比，K为卡尔曼增益。对于迭代卡尔曼滤波，量测更新在每次迭代中重新线性化，直到状态增量收敛。与扩展卡尔曼滤波相比，迭代更新能够降低强非线性场景下的线性化误差。
===[356|学位论文正文]===
协方差的初值和噪声参数对滤波性能影响较大。若过程噪声过小，滤波器对新观测不敏感，运动时容易出现滞后；若过程噪声过大，滤波器对噪声敏感，静止时可能出现抖动。本文采用FAST-LIO2的默认参数，并在仿真中通过观察静止和运动时的轨迹平滑性进行微调。
===[357|Heading 3]===
2.2.2 点云预处理与运动补偿
===[358|学位论文正文]===
激光雷达在扫描一帧点云的过程中，飞机可能已经发生运动。若直接将一帧点云视为同一时刻的观测，会产生运动畸变。运动补偿的基本思路是利用IMU或里程计估计扫描期间的运动，将每个点投影到同一参考时刻。对于机械式激光雷达，点云通常带有逐点时间戳；对于Gazebo仿真的Mid-360点云，逐点时间信息可能缺失，本文只能将整帧点云视为同一时刻，因而在高速运动时会出现一定拖影。
===[359|学位论文正文]===
点云预处理的另一项工作是无效点剔除。仿真中可能产生NaN、inf或距离过近的点，这些点会影响配准和建图。本文在桥接节点中过滤无效点，并设置最小距离阈值，避免飞机自身结构进入地图。最小距离过大会丢失近处障碍，过小会引入自身点云，需要根据机体尺寸和雷达安装位置折中。
===[360|学位论文正文]===
此外，点云的降采样和体素滤波可以降低计算量。FAST-LIO2内部通常对点云进行一定程度的降采样，本文沿用其默认配置。对于探索任务，地图分辨率0.15 m已经足够，过高的点云密度不会显著提高探索效果，反而增加计算负担。
===[361|Heading 3]===
2.3.1 八叉树更新与查询
===[362|学位论文正文]===
OctoMap的更新过程可以看作射线投射与概率累加的组合。对于每一帧点云，从传感器原点向每个点发射射线，射线穿过的体素降低占据概率，射线末端命中的体素提高占据概率。设体素n在第i次观测中的更新量为ΔL(n|z_i)，则
===[363|Normal]===
	Li(n) = max( Lmin, min( Lmax, Li-1(n) + ΔL(n|zi) ) )	(2-20)
===[364|学位论文正文]===
其中L_min和L_max为对数几率上下限，用于抑制噪声和动态障碍的影响。概率上下限与占据/自由阈值共同决定体素状态。若上下限过宽，动态障碍会在消失后长时间保留；若过窄，地图更新过于敏感。
===[365|学位论文正文]===
八叉树的查询包括单点查询、射线查询和包围盒查询。单点查询用于判断某个体素的状态；射线查询用于可见性判断；包围盒查询用于碰撞检查。本文的known-free边检查需要在每个截面查询机体盒覆盖的所有体素，因此包围盒查询的效率直接影响规划速度。OctoMap提供了基于键值的叶节点查找，本文在其基础上实现了轴对齐包围盒的遍历。
===[366|学位论文正文]===
需要注意的是，八叉树的分辨率是离散的。小于分辨率的薄障碍可能被漏检，或者被分配到相邻体素。对于安全关键的应用，应在碰撞检查中增加余量，或者使用更高的分辨率。本文采用0.15 m分辨率和0.7 m机体盒，已在安全性和计算量之间取得折中。
===[367|Heading 3]===
2.4.1 增益与可见性
===[368|学位论文正文]===
增益计算的本质是估计候选视点能看到多少未知体素。设候选视点为x，地图中的体素集合为M，视场为F(x)，则可视体素集合为
===[369|Normal]===
	V(x) = { v ∈ M | visible(x,v) ∧ v ∈ F(x) }	(2-21)
===[370|学位论文正文]===
其中visible(x,v)表示从x到v的射线未被占据体素遮挡。对于每个可视体素，若其状态为unknown，则计入增益；若为free或occupied，则按权重计入或忽略。本文只统计unknown，因此增益等价于可视未知体素的数量。
===[371|学位论文正文]===
为了抑制过远候选点，增益通常乘以距离衰减项。设从根节点到候选节点的距离为d，衰减系数为λ，则最终增益为
===[372|Normal]===
	G(x) = |Vunknown(x)| · exp(-λ d)	(2-22)
===[373|学位论文正文]===
衰减系数λ越大，算法越倾向于近处视点；λ越小，算法越愿意飞到远处。本文取λ=0.5，在仿真中取得了较平衡的效果。若希望探索更快，可以减小λ；若希望更稳健，可以增大λ。
===[374|学位论文正文]===
可见性判断的计算量较大，尤其是候选节点多、地图分辨率高时。常用优化包括：只在一定半径内采样体素、按分辨率步进而非逐体素判断、缓存可见性结果、使用射线投射的增量结构等。本文采用半径限制和步进判断，未实现更复杂的缓存。相关机器人学与规划基础可参考文献[22-25]，占据栅格与SLAM基础可参考文献[26-31]。
===[375|Heading 3]===
2.2.3 状态传播的雅可比
===[376|学位论文正文]===
在误差状态卡尔曼滤波中，状态传播的雅可比矩阵决定了协方差如何增长。设误差状态为δx=[δp, δv, δθ, δb_g, δb_a, δg]，则位置、速度和姿态的误差传播可近似为
===[377|Normal]===
	δpk+1 = δpk + δvk Δt	(2-23)
===[378|Normal]===
	δvk+1 = δvk + (Rk [a]× δθ + Rk δa + δg) Δt	(2-24)
===[379|Normal]===
	δθk+1 = δθk - [ω]× δθk Δt - δbg Δt	(2-25)
===[380|学位论文正文]===
式中：[a]_×和[ω]_×分别为加速度和角速度的反对称矩阵，δa和δb_g为噪声项。雅可比矩阵由上述线性化关系组装而成。实际实现中，FAST-LIO2使用流形上的误差定义，避免姿态参数的奇异性。
===[381|学位论文正文]===
雅可比矩阵的稀疏性和条件数影响滤波稳定性。若某些状态不可观，例如在匀速直线运动中没有足够的加速度激励，协方差会在不可观方向增长，导致估计漂移。探索任务中的运动通常包含转弯和升降，激励较为充分，但在长走廊或悬停时仍可能出现退化。
===[382|Heading 3]===
2.3.2 地图查询接口
===[383|学位论文正文]===
探索器需要频繁查询地图。本文的LocalOctomapManager提供四类接口：单点状态查询、两点可见性查询、包围盒占据查询和线段包围盒查询。单点查询返回unknown/free/occupied；可见性查询沿射线步进，判断是否被occupied遮挡；包围盒查询遍历盒子覆盖的体素；线段包围盒查询沿线段采样，判断机体盒是否与occupied相交。
===[384|学位论文正文]===
接口的返回值和语义必须与探索器一致。例如，getLineStatusBoundingBox返回kFree表示“未发现occupied”，并不表示“全部已知自由”。known-free检查需要额外的isKnownFreeBox接口，要求每个采样点都是free。若把两者混用，就会出现“检查通过但目标在unknown”的问题。
===[385|学位论文正文]===
地图查询的时间复杂度与分辨率、查询范围和八叉树深度有关。为了提高效率，本文在包围盒查询中使用轴对齐范围遍历，避免逐点查询；在线段查询中使用固定步长，减少重复访问。对于大规模地图，可以考虑使用体素哈希或增量式结构，但本文的实验规模不需要。
===[386|Heading 3]===
2.4.2 采样与最近邻
===[387|学位论文正文]===
RRT的采样策略直接影响树的覆盖率。均匀采样实现简单，但在狭窄通道中效率较低；高斯采样、障碍物附近采样和启发式采样可以提高效率，但会增加实现复杂度。本文采用均匀采样，并在工作空间边界处做硬筛选，保证采样点落在有效范围内。
===[388|学位论文正文]===
最近邻查询使用kd-tree。设树中节点数为N，kd-tree的平均查询复杂度为O(log N)。对于每轮几十到几百个节点，查询开销可以忽略；对于大规模树，kd-tree的优势更明显。本文在每个规划周期重建树，节点数有限，因此未使用增量式kd-tree。
===[389|学位论文正文]===
采样点和最近邻的距离计算只使用三维位置，不使用姿态。姿态在节点扩展时随机生成，用于后续的视场判断和执行。由于Mid-360水平视场为360°，姿态对增益的影响较小；若使用相机，姿态需要参与采样和增益计算。
===[390|Heading 3]===
2.4.3 视场与可见性
===[391|学位论文正文]===
视场判断是增益计算的前提。对于相机，视场由四个半空间定义；对于360°激光雷达，水平方向无边界，竖直方向由上下限定义。本文采用仰角带模型，将视场判断简化为
===[392|Normal]===
	flow ≤ arcsin(dz/||d||) ≤ fhigh	(2-26)
===[393|学位论文正文]===
其中d为从候选节点指向体素的方向。为了考虑机体盒和雷达安装高度，本文在上下限附近增加余量，余量随距离增加而减小。该模型不是严格的射线模型，但在中远距离上足够准确。
===[394|学位论文正文]===
可见性判断沿射线步进。若射线在到达体素前遇到occupied，则体素不可见；否则可见。步长通常取地图分辨率的一半到一倍。步长过大会漏检薄障碍，步长过小会增加计算量。本文取0.75倍分辨率，在精度和效率之间折中。
===[395|学位论文正文]===
对于known-free检查，可见性和碰撞是两个不同的问题。可见性回答“能不能看到”，碰撞回答“能不能飞过去”。探索器需要同时考虑二者：增益高的节点可能不可达，可达的节点可能增益低。NBVP通过RRT边检查保证可达性，通过增益保证信息量，二者共同决定最优视点。
===[396|Heading 3]===
2.4.4 采样策略与树结构
===[397|学位论文正文]===
RRT的采样策略决定了树的生长方向和覆盖率。均匀采样实现简单，但在狭窄通道和障碍物附近效率较低；高斯采样可以在已知自由空间附近增加采样密度；启发式采样可以利用地图梯度或前沿信息引导树向未知区域生长。本文采用均匀采样，原因是实现简单、参数少，且局部工作空间较小，均匀采样已足够。
===[398|学位论文正文]===
树结构方面，kd-tree适合最近邻查询，但不支持动态删除；增量式kd-tree支持插入和删除，适合长期运行的建图系统。本文每轮规划重建树，节点数有限，因此使用普通kd-tree。若将规划器改为长期运行或增量式，应考虑增量kd-tree。
===[399|学位论文正文]===
采样和树结构的选择会影响规划时间和覆盖率。采样过多会增加计算量，采样过少会降低覆盖率；树结构过深会增加查询时间，过浅会降低分辨率。本文通过initial_iterations、cutoff和时间片控制采样数量，通过extension_range控制树的深度，在实验中取得了平衡。
===[400|Heading 3]===
2.4.5 工程实现中的坐标变换
===[401|学位论文正文]===
坐标变换在工程实现中通常使用4×4齐次变换矩阵。设T_AB表示从B系到A系的变换，则点p_B在A系中的坐标为p_A = T_AB · p_B。多个变换可以复合：T_AC = T_AB · T_BC。复合顺序不能颠倒，否则结果错误。本文在TF中使用父子关系表示复合，避免手动相乘。
===[402|学位论文正文]===
四元数与旋转矩阵的转换需要注意归一化和符号。旋转矩阵转四元数时，应选择数值稳定的分支；四元数转旋转矩阵时，应先归一化。若四元数未归一化，旋转矩阵可能不满足正交性，导致点云变形。本文在桥接节点和offboard中对四元数做归一化，保证变换正确。
===[403|学位论文正文]===
欧拉角（roll、pitch、yaw）直观，但存在万向锁和顺序依赖。本文只在显示和日志中使用欧拉角，内部计算使用四元数或旋转矩阵。若需要在欧拉角之间插值，应先转换为四元数，插值后再转回，避免奇异。
