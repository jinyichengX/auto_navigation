1. 什么是 SLAM

SLAM = Simultaneous Localization and Mapping，中文：同时定位与地图构建。

一句话解释

把一个机器人放进完全陌生的环境，不给它任何地图。让它一边探索，一边在脑子里画地图，同时时刻知道自己在哪。

拆开看三个词

Simultaneous 同时

不是「先建图再定位」也不是「先定位再建图」。两者必须同时进行，因为它们互相依赖。

Localization 定位

回答「我在哪里？」——确定机器人在空间中的位置坐标和朝向角度。在 2D 平面中就是 (x, y, θ) 三个数。

Mapping 建图

回答「周围长什么样？」——构建环境的几何模型。通常是一张「占据栅格地图」，告诉你哪里能走、哪里是墙。

为什么 SLAM 是机器人学的「圣杯问题」之一

在过去 30 年里，SLAM 从一个「理论上可能不存在解」的问题，演变为「室内场景已基本解决」的问题。这个过程浓缩了概率机器人学、稀疏矩阵计算、非线性优化的几乎所有核心进展。理解了 SLAM，你就理解了机器人如何「认知空间」。

SLAM 的哲学意义：它探讨的是一个根本问题——一个智能体如何在没有外部参照的情况下，仅凭传感器和自身运动，构建对世界的认知。这个问题在生物学（动物如何导航）、神经科学（海马体位置细胞）和人工智能（空间智能）中都有对应。

2. 蒙眼探房间 — 人类如何不靠视觉导航

在进入数学之前，先用一个生活中的类比建立直觉。

场景设定

想象你被蒙上眼睛，推进一个完全陌生的房间。你不知道房间多大、什么形状、有没有家具。你只能做两件事：

  1. 伸手摸 — 感知前方、左右有没有墙壁或障碍物。这叫「观测」。
  2. 数步子 — 走几步大概知道移动了多少。这叫「里程计」。
第 1 步
图 1：蒙眼人在未知房间中探索的四个步骤。左侧是真实房间，右侧是脑中构建的地图。

你会发现什么

  • 第一步摸到墙 → 知道「房间边界在这里」→ 在脑中画一条线段
  • 走几步 → 步子数得不精确，可能多走了半米或少走了半米 → 脑中地图开始变形
  • 再摸 → 发现「咦，这个墙角我好像摸过？」→ 回头修正脑中地图
  • 回到起点附近 → 「啊，这里是我最开始摸的地方！」→ 回环闭合，地图被「拉正」

这四步恰好对应了 SLAM 的四个核心操作：局部建图 → 里程计更新 → 扫描匹配 → 回环检测与全局优化。

人类的这套「蒙眼导航系统」在神经科学中称为路径整合（Path Integration），由海马体中的位置细胞（place cells）和网格细胞（grid cells）实现。SLAM 算法在很多方面模仿了这个生物机制。

3. 机器人如何「看」世界 — 外部感知传感器

机器人没有眼睛和手，但有传感器。SLAM 依赖两大类传感器：外部感知传感器（看世界）和内部运动传感器（感受自己）。本章先讲前者。

3.1 激光雷达 (LiDAR) slam_toolbox 使用的

LiDAR = Light Detection and Ranging。工作原理：发射一束激光脉冲 → 碰到物体反射回来 → 测量往返时间 → 距离 = 光速 × 时间 / 2。

2D LiDAR 输出的数据长什么样

一个 360° 的 2D LiDAR 每转一圈，输出一个数组，里面是几百个距离值。比如：

// sensor_msgs/LaserScan 的核心字段（简化表示）
angle_min: -3.14      // 扫描起始角度（-180°）
angle_max:  3.14      // 扫描结束角度（+180°）
angle_increment: 0.01745  // 每个测距点间隔（1°）
ranges: [2.3, 2.3, 2.2, 1.8, 1.5, 0.9, 0.5, 0.5, 0.6, 1.0, 1.5, 2.0, ...]
//       ↑正前方2.3m  ↑左前1.8m  ↑左侧0.5m(墙)   ↑右前1.5m
图 2：2D LiDAR 扫描示意。红点 = 激光击中的障碍物，绿色虚线 = 激光射线。右侧是距离数组的极坐标可视化。

LiDAR 的优点

  • 精度高（厘米级甚至毫米级）
  • 不受光照影响（黑暗中也能工作）
  • 360° 全覆盖（2D LiDAR）
  • 数据简单：就是一堆距离值，处理快

LiDAR 的局限

  • 无法感知颜色和纹理
  • 透明物体（玻璃）、镜面反射会测不准
  • 强阳光下性能下降
  • 3D LiDAR 昂贵（几千到几万元），2D 便宜（几百元）

3.2 视觉相机 (Camera)

RGB 相机输出图像，通过提取特征点（角点、边缘）来做 SLAM。分三种：

类型输出优点缺点代表方案
单目 (Monocular)2D 图像最便宜、体积小有尺度歧义（不知道实际大小）ORB-SLAM3
双目 (Stereo)2D 图像 + 视差深度有真实尺度需要标定、计算量大VINS-Fusion
RGB-D2D 图像 + 深度图直接获取深度室外强光失效、量程短RTAB-Map
本文第 21 章开始讲的 slam_toolbox 只使用 2D LiDAR，不使用视觉。之所以提视觉 SLAM，是为了让你理解整个 SLAM 生态的全貌。如果你只关心 slam_toolbox 实战，可以跳过视觉相关内容。

3.3 毫米波雷达 (Radar)

发射电磁波、测量反射。优点是穿透雨雾烟尘，缺点是角分辨率低（几个弧度 vs. LiDAR 的零点几度）。在自动驾驶中用作 LiDAR 的补充，slam_toolbox 不支持。

4. 机器人如何「感受」自己 — 内部运动传感器

外部传感器告诉你「世界长什么样」，内部传感器告诉你「我动了多少」。

4.1 轮式里程计 (Wheel Odometry) 最常见的运动源

原理极其简单：

  • 电机编码器记录轮子转了多少圈 → 乘以轮子周长 → 得到走了多远
  • 左右轮差速 → 算出转了多少角度

差速驱动机器人的里程计公式

设左右轮分别走了 dL 和 dR 的距离，轮距为 B：

d_center = (d_L + d_R) / 2 ← 中心前进了多少 d_theta = (d_R - d_L) / B ← 转了多少弧度 x_new = x_old + d_center × cos(θ_old + d_theta/2) y_new = y_old + d_center × sin(θ_old + d_theta/2) θ_new = θ_old + d_theta
里程计的致命问题：漂移。轮子打滑、地面不平、轮胎气压变化、轮径磨损——所有这些都会让里程计产生误差。而且误差会随时间累积：1 秒偏 1 厘米，60 秒偏 60 厘米，5 分钟偏 3 米。没有外部纠正的话，机器人对自己位置的认知会像醉汉一样越走越偏。

4.2 惯性测量单元 (IMU)

IMU 包含两个传感器：

  • 加速度计：测量三个轴的线性加速度（m/s²）→ 积分两次得位移（但漂移极其严重）
  • 陀螺仪：测量三个轴的角速度（rad/s）→ 积分一次得角度（短期较准）

IMU 的特点是：短期精度高（100-1000Hz 高频输出），但积分漂移随时间的平方增长。单独用 IMU 做定位，10 秒后偏几度，1 分钟后角度完全不可信。

4.3 里程计和 IMU 怎么互补

传感器优势劣势融合后的收益
轮式里程计平移精度尚可（厘米级/秒漂移）转弯时误差大、打滑会跳变提供平移先验
IMU旋转精度高（零点几度/秒漂移）平移积分漂移巨大提供旋转先验
两者融合用 EKF（扩展卡尔曼滤波）融合 → 定位精度提高 2-5 倍工程标准做法

ROS 2 中通常用 robot_localization 包来融合里程计和 IMU，输出更精确的 /odom 话题。slam_toolbox 不直接使用 IMU，但它会受益于更精确的里程计输入。

slam_toolbox 的标准输入公式：
/scan（激光数据，必需）+ /odom（里程计，强烈推荐）+ TF 坐标变换树（必需）
缺少任何一个，SLAM 要么跑不起来，要么精度大幅下降。

5. 鸡与蛋的死锁 — SLAM 的核心矛盾

现在你知道了传感器怎么工作。但为什么 SLAM 是一个「难题」？因为以下这个看似无解的矛盾：

图 3：SLAM 的鸡-蛋死锁。建图需要位姿 → 定位需要地图 → 形成闭环依赖。

为什么不能「先建图再定位」？

建图的本质是把多个时刻的激光扫描「拼」在一起。但每次扫描是以机器人为原点的极坐标数据（前方 2m 有障碍、左方 0.5m 有墙……）。要把这些局部数据转换到统一的全局坐标系中，必须知道每次扫描时机器人的精确位姿 (x, y, θ)。

一个具体例子

机器人在 t=1 时刻，扫描到前方 2m 有墙。它当时在位置 (0, 0)，面朝 0°。所以这堵墙在全局坐标系的 (2, 0) 位置。

机器人在 t=2 时刻，又扫描到「前方 2m 有墙」。但此时机器人在哪？如果它在 (1, 0)，那这堵墙在 (3, 0)——注意，和上一堵墙不是同一个！如果它在 (0, 0) 但在原来位置的右边 0.1m（由于里程计漂移），那这堵墙在 (2.1, 0)——本来应该是同一堵墙，现在偏了 0.1m。

没有精确位姿，就无法把不同时刻扫描到的「同一堵墙」正确重合在一起。

为什么不能「先定位再建图」？

定位需要把当前扫描与已有地图做匹配，找到匹配度最高的位置。但如果没有地图，就没有可以匹配的参照物。

纯靠里程计行不行？可以撑几秒钟——但在那之后，漂移会累积到不可接受的程度。只靠里程计定位，机器人实际上在「盲走」。

SLAM 的数学本质：SLAM 把「建图需要位姿」和「定位需要地图」这两个互相依赖的问题，放在同一个联合概率框架里同时求解。不是先后做，而是把两者作为一个统一的优化问题，让位姿和地图互相约束、共同收敛。

6. 为什么要用概率

进入数学部分之前，先回答一个看似哲学的问题：为什么 SLAM 必须用概率？为什么不能直接算出确定的值？

因为世界充满不确定性

SLAM 中的不确定性来自三个源头：

传感器噪声

LiDAR 测 2.00m 不一定真的是 2.00m，可能实际是 2.02m 或 1.98m。每个测量都带有随机误差。

运动噪声

里程计说「前进了 0.50m」但真实移动可能是 0.47m（打滑）或 0.53m（轮径偏大）。

环境不确定性

地图本身是不确定的——「前方是墙」不是 100% 确定，而是「95% 概率是墙，5% 概率是传感器噪点」。

确定性 vs 概率性：一个思想实验

假设你在一个 1 米宽的长走廊里，闭着眼睛向前走。里程计说走了 10m。你知道自己在哪吗？

  • 确定性思维：「我在 (10, 0)」→ 这是错的，因为里程计有漂移
  • 概率性思维：「我在以 (10, 0) 为中心、方差 0.5m 的高斯分布中」→ 这才是对的

概率不仅更诚实，而且更有用。当新传感器数据进来时（比如摸到墙在 y=0.5 的位置），你可以用贝叶斯公式把先验（里程计说你在 (10, 0)）和新观测（墙在 y=0.5）融合起来，得到更精确的后验估计。

SLAM 的核心洞察：不确定性的量化和传播比确定性估计更重要。一个能精确知道自己「有多不确定」的系统，比一个给出错误确定值的系统要强得多。

7. 高斯分布：不确定性的通用语言

在 SLAM 中，几乎所有不确定性都用高斯分布（正态分布）表示。为什么？三个原因：

  1. 中心极限定理：大量独立噪声的叠加趋近高斯分布——传感器噪声恰好满足这个条件
  2. 计算友好：高斯分布只用两个参数描述（均值 μ 和方差 σ²），且多个高斯的运算（加减乘、条件化）仍产出高斯
  3. 最大熵性质：在只知道均值和方差的情况下，高斯分布是「最不武断」的选择

一维高斯

p(x) = (1 / √(2πσ²)) × exp( -(x - μ)² / (2σ²) )

μ（均值）= 最可能的值（钟形曲线的顶点）；σ（标准差）= 不确定性的宽度（σ 越小越确定）

多维高斯

机器人位姿是 3 维的 (x, y, θ)，需要用多元高斯分布：

p(x) = (1 / √((2π)^k |Σ|)) × exp( -½ (x - μ)^T Σ^{-1} (x - μ) )
  • μ（均值向量）：最可能的位姿，如 [1.0, 0.5, 0.3]
  • Σ（协方差矩阵）：描述不确定性的形状和方向
图 4：二元高斯分布的不确定椭圆。左：x 和 y 独立（协方差 = 0）。中：x 和 y 正相关（你往东偏了，往往也往北偏）。右：负相关。

协方差矩阵的意义

在 SLAM 中理解协方差矩阵 Σ 非常关键。比如机器人的位姿协方差可能长这样：

Σ = ┌                    ┐
    │ 0.04   0.00  -0.01 │   ← x 方差 0.04（标准差 ±0.2m）
    │ 0.00   0.01   0.00 │   ← y 方差 0.01（标准差 ±0.1m）
    │ -0.01  0.00   0.02 │   ← θ 方差 0.02（标准差 ±0.14rad ≈ ±8°）
    └                    ┘

负的非对角元素 (-0.01) 说明 x 和 θ 之间存在负相关——前进方向的误差和角度误差互相影响。这种相关性在 SLAM 中非常重要，因为误差会沿着相关路径传播。

扩展到 SLAM：在 EKF-SLAM 中，状态向量包含机器人位姿 + 所有路标的位置，协方差矩阵维度可以高达数千维。矩阵中的每一个非零块都表示「这两个估计值如何一起漂移」。维护这个巨大的协方差矩阵正是 EKF-SLAM 计算复杂度的根源。

8. 运动模型 — 预测的艺术

运动模型（Motion Model）回答一个问题：给定上一时刻的位姿和当前运动指令，机器人现在最可能在哪？

8.1 速度运动模型

输入：上一时刻位姿 xt-1 = (x, y, θ) + 控制指令 ut = (v, ω)（线速度和角速度）
输出：当前位姿的概率分布 p(xt | xt-1, ut)

在理想情况下（没有噪声），运动学公式为：

x' = x - (v/ω)·sinθ + (v/ω)·sin(θ + ω·Δt) y' = y + (v/ω)·cosθ - (v/ω)·cos(θ + ω·Δt) θ' = θ + ω·Δt （当 ω ≈ 0 时，退化为直线运动：x' = x + v·Δt·cosθ, y' = y + v·Δt·sinθ, θ' = θ）

8.2 噪声模型

现实中的运动有噪声。把噪声建模在控制指令本身上（而非结果上）：

v̂ = v + ε_v （ε_v ∼ N(0, α₁·v² + α₂·ω²)） ω̂ = ω + ε_ω （ε_ω ∼ N(0, α₃·v² + α₄·ω²)）

这里的 α₁ 到 α₄ 是需要标定的运动噪声参数。它们反映了机器人运动学模型的精度。

8.3 里程计运动模型（slam_toolbox 实际使用的）

slam_toolbox 不使用速度运动模型，而是直接从里程计数据中提取相对运动——因为 ROS 2 中里程计直接给出了 (Δx, Δy, Δθ) 的相对变换。运动模型简化为：

x_t = x_{t-1} ⊕ δ_odom （⊕ 表示 SE(2) 上的复合运算）

其中 δ_odom 是从 /odom 话题中提取的两帧之间的相对变换。噪声被建模为 δ_odom 的不确定性。

运动模型本质上是在「猜」——它基于物理规律预测机器人到了哪。但由于噪声，这个猜测是一个概率分布，而非确定值。下一章的观测模型则负责「纠正」这个猜测。

9. 观测模型 — 感知的数学

观测模型（Observation Model）回答：给定机器人位姿和地图，传感器应该看到什么？

9.1 LiDAR 的观测模型

给定位姿 x 和地图 m，激光束沿方向 φ 击中的预期位置通过射线投射（Ray Casting）计算：

z_expected = raycast(m, x, φ) 真实测量 z_actual 与 z_expected 的差 = 需要修正的量

9.2 似然域模型（Likelihood Field）

直接做射线投射很慢（每条射线都要在栅格地图中追踪），所以 slam_toolbox 使用的是似然域模型：

  1. 预计算一张「距离地图」——每个栅格存储该栅格到最近障碍物的距离
  2. 将激光终点投影到这张图上 → 查表得到距离 d
  3. 似然度 = 高斯分布在距离 d 处的取值 → 离障碍物越近，似然越高
p(z | x, m) ∝ exp( -d² / (2σ²) )

其中 d 是激光终点到最近障碍物的距离，σ 是激光噪声的标准差。

9.3 观测如何「纠正」位姿

运动模型说「你大概在位置 A」。观测模型说「如果你在位置 A，你看到的应该像 X；但实际上你看到的是 Y」。X 和 Y 的差异 = 需要修正的量。这个「预测 vs 实际」的差异，就是 SLAM 优化的驱动力。

图 5：预测 vs 实际观测。运动模型预测机器人到了 A 点（红色虚线）。但实际激光扫描（红色点）与地图的匹配显示机器人在 A' 点（更近处）。误差（蓝色箭头）被用来修正位姿估计。

10. 贝叶斯滤波 — SLAM 的数学心脏

贝叶斯滤波是所有概率 SLAM 方法（EKF、FastSLAM、信息滤波）的共同数学基础。它用简洁的两步递归实现了从噪声数据中持续更新信念（belief）的目标。

我们把 SLAM 的形式化如下：

10.3 贝叶斯递归两步曲

第 1 步：预测 (Prediction)

根据上一时刻的信念 + 当前运动，预测当前位姿的先验分布：

bel⁻(x_t, m) = ∫ p(x_t | x_{t-1}, u_t) · bel(x_{t-1}, m) · dx_{t-1}

这一步增加不确定性——因为运动有噪声，你对位置的信念变得更模糊。

第 2 步：更新 (Correction)

用新观测修正预测，得到后验分布：

bel(x_t, m) = η · p(z_t | x_t, m) · bel⁻(x_t, m)

这一步减少不确定性——传感器提供了新信息。η 是归一化常数。

10.4 从贝叶斯到具体算法

贝叶斯递推公式虽然理论优美，但积分在大多数情况下没有闭式解。不同的 SLAM 算法家族就是在不同的近似策略下求解贝叶斯递推：

  • EKF-SLAM：假设所有分布是高斯，用一阶泰勒展开线性化 → 得到 Kalman 滤波公式（第 12 章）
  • FastSLAM：用粒子集合近似任意分布 → 得到粒子滤波公式（第 13 章）
  • GraphSLAM：用信息矩阵形式重写贝叶斯递推，转化为非线性最小二乘（第 14 章）
理解贝叶斯递推，就理解了所有 SLAM 算法为什么长那样。EKF-SLAM 的高斯假设、FastSLAM 的粒子采样、GraphSLAM 的信息矩阵——都是对这个统一框架的不同近似实现。

11. 最小二乘 — 优化即一切

现代 SLAM 的本质可以浓缩为一句话：把 SLAM 转化为一个大规模非线性最小二乘问题，然后用数值优化求解。

11.1 从最大似然到最小二乘

在 SLAM 中，我们想找到使观测概率最大化的位姿和地图：

x* = argmax ∏ p(z_t | x_t, m) x,m t

假设噪声是高斯分布：p(z | x, m) ∝ exp(-½||e(x)||²)，取负对数后最大化变成最小化：

x* = argmin Σ ||e_t(x_t, m)||² x,m t

这就是一个非线性最小二乘问题。e_t 是误差函数（观测值与预测值的差异）。

11.2 高斯-牛顿法 (Gauss-Newton)

对误差函数在当前位置做一阶泰勒展开：

e(x + Δx) ≈ e(x) + J · Δx

其中 J = ∂e/∂x 是 Jacobian 矩阵。代入目标函数并令导数为 0：

(J^T J) · Δx = -J^T · e(x) H Δx = -b

这就是正规方程（Normal Equation）。解出 Δx，更新 x ← x + Δx，重复直到收敛。

11.3 列文伯格-马夸尔特 (Levenberg-Marquardt, LM)

高斯-牛顿法在初始值较差时可能发散。LM 算法增加了一个阻尼项：

(H + λ·I) · Δx = -b

λ 是阻尼因子：λ 大 → 接近梯度下降（稳定但慢）；λ 小 → 接近高斯-牛顿（快但可能不稳定）。LM 动态调整 λ，兼顾速度和鲁棒性。slam_toolbox 默认使用 LM 算法。

11.4 为什么 SLAM 中的 H 矩阵是稀疏的

这是图优化 SLAM 能高效运行的关键原因。在位姿图中，每个误差项 eij 只涉及两个节点 i 和 j。因此 Jacobian J 中只有两个非零块。当构建 H = J^T J 时，H 只在 (i,i)、(i,j)、(j,i)、(j,j) 处有非零块。

结果：一个有 10000 个节点的位姿图，H 是 30000 × 30000 的矩阵，但仅有约 10 万个非零元素（而非 9 亿个）。利用稀疏 Cholesky 分解，可以在几十毫秒内求解。

图优化 SLAM 为何能取代 EKF-SLAM：正是因为利用了 H 的稀疏性。EKF-SLAM 维护的是稠密的协方差矩阵（O(N²) 内存和 O(N²) 时间），而图优化利用稀疏性做到了近 O(N) 的复杂度。

12. EKF-SLAM — 卡尔曼滤波的荣光与局限

EKF-SLAM 是最早的实用 SLAM 算法（1990年代），奠定了概率 SLAM 的理论基础。虽然现在工业界基本不用了，但理解它对于理解 SLAM 的数学本质至关重要。

12.1 核心思想

把机器人位姿 + 所有路标位置放进一个巨大的状态向量中，用扩展卡尔曼滤波递归地更新这个状态的均值和协方差矩阵。

状态向量结构

μ = [x y θ m₁,x m₁,y m₂,x m₂,y ... mₙ,x mₙ,y]^T

维度 = 3（位姿） + 2N（N 个路标）。如果有 100 个路标，状态向量就是 203 维。

12.2 预测步骤

当机器人运动时，只更新位姿部分的状态。运动模型（速度模型）为：

x_new = x - (v/ω)·sinθ + (v/ω)·sin(θ + ω·Δt) y_new = y + (v/ω)·cosθ - (v/ω)·cos(θ + ω·Δt) θ_new = θ + ω·Δt

Jacobian G 对位姿求导（3×3 矩阵），用于协方差传播：

Σ_new = G · Σ · G^T + R （R 是运动噪声协方差）

因为运动不影响路标位置，所以预测步骤只更新 Σ 的位姿相关块——计算量不算大。

12.3 更新步骤

当观测到路标时，用观测方程计算期望观测值与实际观测值的差异（innovation ν）：

ν = z - h(μ̄) （h 是观测方程：位姿 + 路标位置 → 期望的极坐标观测）

计算卡尔曼增益 K：

K = Σ̄ · H^T · (H · Σ̄ · H^T + Q)^{-1}

其中 H 是观测方程对状态向量的 Jacobian（2 × (3+2N) 矩阵），Q 是传感器噪声协方差。

更新均值和协方差：

μ = μ̄ + K · ν Σ = (I - K·H) · Σ̄

12.4 EKF-SLAM 的致命问题

计算复杂度 O(N²)

协方差矩阵 Σ 是 (3+2N)×(3+2N) 的。每次更新需要 O(N²) 时间。N=1000 时，Σ 有 4 百万个元素，更新一次耗时数十毫秒。N=10000 时，Σ 有 4 亿个元素，完全不现实。

线性化误差累积

EKF 假设系统是局部线性的。但 SLAM 的角度变量有很强的非线性（at rigonometric functions）。每次预测用当前估计点做线性化，误差逐渐累积。这叫 EKF 的不一致性（inconsistency）。

数据关联不可逆

EKF 假设观测和路标之间的对应关系是已知的。如果错误地把路标 A 的观测关联到了路标 B，协方差矩阵会把错误传播到所有变量。而且没有回头路可走——EKF 是前向滤波，不能「撤回」过去的错误关联。

12.5 信息形式：EIF-SLAM

EIF（Extended Information Filter）使用信息矩阵 Λ = Σ^(-1) 代替协方差。更新步骤变成简单的加法：

Λ_new = Λ_old + H^T · Q^(-1) · H （只需加法！）

但预测步骤变复杂了。更重要的是，信息矩阵近似稀疏（远距离路标之间的信息接近零），这为图优化方法铺平了道路。

EKF-SLAM 的历史地位：它在 1990 年代末首次证明了「概率 SLAM 是可行的」。但它的 O(N²) 复杂度使其只能处理几十个路标的小场景。2000 年代中期，粒子滤波和图优化方法相继取而代之。

13. FastSLAM — 粒子滤波的智慧

FastSLAM 利用了一个巧妙的数学分解，把 O(N²) 的 EKF-SLAM 降到了 O(M·log N)（M 是粒子数）。

13.1 核心洞察：条件独立

给定机器人的完整轨迹，不同路标之间的估计是条件独立的。也就是说：

p(x_1...x_t, m_1, m_2 | z_1...z_t, u_1...u_t) = p(x_1...x_t | z_1...z_t, u_1...u_t) × p(m_1 | x_1...x_t, z_1...z_t) × p(m_2 | x_1...x_t, z_1...z_t) × ...

这被称为 Rao-Blackwellized 粒子滤波（RBPF）：

  • 用粒子滤波器估计轨迹分布（每个粒子是一条可能的轨迹）
  • 每个粒子内部，用K 个独立的 EKF 分别估计 K 个路标（每个路标 2×2 协方差矩阵）

  1. 运动预测：用运动模型得到先验位姿估计 μ⁻ 和协方差 Σ⁻
  2. 观测融合：用观测 z_t 做 EKF 更新，得到后验位姿 μ⁺ 和 Σ⁺
  3. 从后验分布中采样：x_t^(k) ~ N(μ⁺, Σ⁺)

由于使用了观测信息来「引导」采样，大多数粒子都落在高似然区域，权值方差大幅降低。

13.3 重采样与粒子退化

随着时间推移，少数粒子获得极高权重，多数粒子权重趋近零（粒子退化）。策略：

  • 计算有效样本数：N_eff = 1 / Σ w_k²
  • 当 N_eff 低于阈值（如 M/2）时触发重采样：按权重比例复制高权重粒子、丢弃低权重粒子
  • 重采样后所有权重重置为 1/M
重采样的副作用：高权重粒子被过度复制，导致粒子多样性丧失。对于回环闭合场景，过去轨迹的粒子已经被「锁定」为错误的副本——这就是为什么纯粒子滤波 SLAM 在回环闭合方面远不如图优化方法。

13.4 GMapping：FastSLAM 的最著名实现

GMapping 是 ROS 1 时代最流行的 2D SLAM 方案，基于 FastSLAM 2.0 + 改进的提议分布 + 自适应重采样。但它：不支持 ROS 2 原生、没有回环检测模块、在大场景中粒子退化严重。slam_toolbox 是它的精神继承者，但改用图优化方法解决了 GMapping 的这些痛点。

14. GraphSLAM — 图优化的崛起

2000 年代末，随着稀疏线性代数库（CHOLMOD、CSparse）的成熟，图优化方法全面超越滤波方法，成为现代 SLAM 的事实标准。slam_toolbox 就是图优化 SLAM。

14.1 图是什么

图 SLAM 把问题建模为一个图：

  • 节点（Node）：某个时刻的机器人位姿 x_t = (x, y, θ)
  • 边（Edge）：两个节点之间的相对变换约束 T_ij = (Δx, Δy, Δθ)，表示「从节点 i 走到节点 j 应该经历怎样的变换」

14.3 误差函数与优化目标

每条边定义了一个期望的相对变换 T_ij。如果节点 i 和 j 的实际位姿差不等于 T_ij，就产生了误差：

e_ij(x_i, x_j) = (x_j ⊖ x_i) ⊖ T_ij

其中 ⊖ 是 SE(2) 流形上的减法。全图的优化目标为：

x* = argmin Σ (e_ij)^T · Ω_ij · e_ij x 所有边(i,j)

Ω_ij 是信息矩阵（= 协方差的逆），反映该约束的可信度。可信度高的边权重更大。

14.4 用高斯-牛顿法求解

对误差函数线性化：e(x + Δx) ≈ e + J·Δx。代入目标函数：

E = Σ (e_ij + J_ij·Δx)^T · Ω_ij · (e_ij + J_ij·Δx) = const + 2·b^T·Δx + Δx^T·H·Δx

其中：

H = Σ J_ij^T · Ω_ij · J_ij （Hessian，信息矩阵） b = Σ J_ij^T · Ω_ij · e_ij （梯度）

令导数为零：H·Δx = -b。求解这个稀疏线性系统得到 Δx，更新 x ← x + Δx，迭代至收敛。

14.5 SPA（Sparse Pose Adjustment）- slam_toolbox 后端

SPA 是专门为 2D SLAM 位姿图优化设计的算法：

  • 利用 SE(2) 的特定代数结构提供闭式 Jacobian（无需 AutoDiff）
  • 稀疏 Cholesky 分解（CSparse/CHOLMOD）高效求解 H·Δx = -b
  • 增量式求解：新节点加入时仅更新受影响的局部子图
  • LM 阻尼保证收敛

SPA 由 Konolige 等人在 2010 年提出，是 slam_toolbox 后端优化的核心。与通用 Ceres/g2o 求解器相比，SPA 利用 2D 几何结构做了大量优化，速度更快。

15.1 为什么现代 SLAM 选择了图优化

三个关键转折点：

  1. 2008 年，iSAM 论文：证明了图优化可以通过增量 QR 分解做到实时。此前图优化被认为「只能离线用」。
  2. 2010 年，SPA 论文：专门针对 2D SLAM 优化，利用 SE(2) 特性大幅提速。
  3. 2012 年，iSAM2 论文：引入 Bayes 树，实现了 O(log N) 的增量更新。

三个里程碑使得图优化在精度和速度上全面超越滤波方法。今天，所有主流 SLAM 系统（slam_toolbox、Cartographer、ORB-SLAM3）都是图优化的不同变体。

如果你只记得一件事的话：滤波 = 只关心当前状态（计算快但无法回退修正）。图优化 = 关心全部历史（计算量大但精度最高）。slam_toolbox 选择了图优化，但用异步架构解决了实时性问题。

16. 前端：扫描匹配 — 帧与帧的对齐

扫描匹配是 SLAM 前端最核心的操作。输入：两帧激光扫描（或一帧扫描 + 已有地图）+ 里程计初值。输出：一个更精确的相对位姿变换。

16.1 ICP：迭代最近点 最经典

ICP 的算法流程极其简洁：

  1. 找对应点：对扫描 A 的每个点，在扫描 B 中找到最近的点作为对应
  2. 算变换：用这些对应点对，通过 SVD 分解计算最优的旋转 R 和平移 t，使得对应点间的欧式距离平方和最小
  3. 应用变换：把 A 用 (R, t) 变换到新位置
  4. 重复：回到步骤 1，直到变换量小于阈值或达到最大迭代次数

Point-to-Plane ICP点到切面距离快（二次收敛）3D LiDAR、表面光滑
PL-ICP点到线段距离快（二次收敛）2D 室内（墙是线段）
G-ICP概率化的点-点距离中泛用（统一框架）
ICP 的最大弱点：依赖初始值。如果里程计给的初始变换太差（比如旋转差了 30°），ICP 会收敛到局部最优而非全局最优。这就是为什么里程计必须「大方向对」——即使细节有误差。

16.3 Karto 相关性匹配：slam_toolbox 的选择

slam_toolbox 使用的是 Karto Scan Matcher，基于相关性匹配而非 ICP。工作原理：

  1. 以里程计初值为中心，构造一个搜索窗口（如 ±0.3m, ±0.3rad）
  2. 在搜索窗口内枚举所有候选位姿，对每个候选位姿计算「当前扫描与已有地图的重合度得分」
  3. 得分 = 激光点落在「占据栅格」上的数量。得分越高 = 匹配越好
  4. 先粗搜索（0.05m 分辨率），找到最高分区域 → 再细搜索（亚像素）精确定位

Karto vs ICP 对比

维度Karto 相关性匹配ICP
原理暴力搜索最优分（网格搜索）迭代最近点对（梯度下降）
初始值敏感度较低（搜索窗口内找到全局最优）较高（易陷入局部最优）
计算量取决于搜索窗口大小和分辨率取决于迭代次数和点数
2D 场景专为 2D 设计，效果优异通用，2D/3D 均可

16.4 NDT（正态分布变换）

NDT 把点云划分为栅格，每个栅格内的点用正态分布（均值 + 协方差）近似。匹配时不是点对点，而是最大化「新扫描点落在对应栅格正态分布下的概率」。优点是不需要显式找对应点，缺点是依赖于栅格大小的选择。

17.4 Sync vs Async：优化的时机差异

Sync 模式

扫描匹配和优化在同一线程。优化时阻塞新扫描——可能丢帧。简单直接，适合小场景（<1000 节点）。

Async 模式 推荐

扫描匹配和优化在不同线程。新扫描不断来，前端做局部匹配。后端优化异步执行。不丢帧，适合大场景。

18. 回环检测：SLAM 的灵魂

没有回环检测的 SLAM = 高级里程计。回环检测是 SLAM 区分于纯里程计的最本质特征。

18.1 为什么回环这么重要

机器人绕房间走一圈回到起点。由于里程计漂移，估计的轨迹（红色）严重偏离真实轨迹（绿色），起点和终点对不上——误差可能高达数米。回环检测识别出「这个地方我来过」，在当前位置和起点之间添加约束边，优化时把所有误差重新分配，「拉正」整条轨迹。

图 9：回环检测与修正的四个阶段。绿色 = 真实轨迹，红色虚线 = 里程计估计。回环检测在步骤 3 发现「回到了起点附近」，步骤 4 优化后轨迹被拉正。

18.2 回环检测四步流程

  1. 候选搜索：在关键帧数据库中搜索与当前帧相似的历史帧。slam_toolbox 支持局部搜索（当前位姿附近 N 米内）和全局搜索
  2. 相似度计算：用扫描匹配得分（当前扫描与候选位置处的地图重合度）作为相似度量。得分 > 阈值 = 回环候选
  3. 几何验证：候选不等于真回环！需要跑一次更精细的扫描匹配来确认。匹配上且误差在合理范围 → 真回环
  4. 添加约束边：在当前节点和历史节点之间添加一条回环约束边，送入后端优化

18.3 slam_toolbox 回环参数

do_loop_closing: true                # 是否启用回环检测
loop_closure_max_scans: 10           # 每次回环检查考虑的扫描帧数
loop_closure_search_radius: 2.0      # 局部搜索半径（米）
loop_closure_min_response: 0.3       # 粗匹配最低得分（0-1）
loop_closure_min_response_fine: 0.4  # 精细验证最低得分（0-1）
建图时最重要的是走出去再走回来。让机器人回到起点附近、在已经建图的区域多走几次。这能触发回环检测，极大提升地图一致性。没有回环的建图 = 白建。

18.4 全局回环方法（拓展）

slam_toolbox 用的是「扫描到地图」的回环检测。在学术界和工业界还有更高级的方法：

  • Scan Context（Kim, 2018）：将 3D 点云编码为 2D 矩阵描述子，对旋转不变。用于 LiDAR 位置识别
  • DBoW2（Gálvez-López, 2012）：视觉词袋模型，把图像表示为视觉单词的直方图。ORB-SLAM3 使用
  • Branch-and-Bound（Hess, 2016）：Cartographer 使用的，保证找到全局最优匹配的分支定界搜索

19.2 概率更新公式

每个栅格存储的不是「是/否」而是占据概率的后验对数几率（log-odds）：

l_t = log( p(occ | z_1...z_t) / p(free | z_1...z_t) )

新观测进来时，用加法更新：

l_t = l_{t-1} + log( p(z | occ) / p(z | free) ) - l_0

其中 l_0 是先验对数几率（如果初始不知道，通常 l_0 = 0，即 p=0.5）。

用对数几率的好处：

  • 更新是加法（而非乘法和归一化），数值稳定
  • 不会因为大量观测而溢出
  • 可以方便地转换为概率：p = 1 / (1 + exp(-l))

19.3 从激光扫描到栅格更新

对于每一束激光（从机器人位姿出发，沿角度 φ，距离 d）：

  • 激光穿过的所有栅格 → 标记为空闲（用 Bresenham 算法找到所有沿线栅格）
  • 激光末端（障碍物）的栅格 → 标记为占据

22.1 Online Sync：简单直接

每收到一帧激光扫描，同步处理：扫描匹配 → 更新位姿图 → 更新地图。处理完才接收下一帧。

  • 优点：实时性好，地图更新即所见即所得
  • 缺点：大场景全局优化耗时长，可能丢帧
  • 适用：小场景（< 500 m²）

22.2 Online Async：工业级标准 99% 场景用这个

扫描匹配和全局优化在不同线程中异步运行：

  • 匹配线程：持续接收激光帧，做局部扫描匹配，更新局部地图
  • 优化线程：在后台异步执行全局位姿图优化，优化完成后更新全局地图

两个线程共享位姿图数据结构（通过互斥锁同步）。

  • 优点：不丢帧，全局优化不阻塞实时匹配
  • 缺点：地图更新有延迟（通常 <1 秒）
  • 适用：大场景、高帧率 LiDAR

22.3 离线模式 (Offline)

输入 rosbag 文件，批量处理所有数据。核心价值：可以对同一个 bag 多次运行、调参、对比，产出最优地图。

ros2 launch slam_toolbox offline_launch.py

在 mapper_params_offline.yaml 中指定 bag 文件路径：

# mapper_params_offline.yaml
slam_toolbox:
  ros__parameters:

22.4 终身建图 (Lifelong)

不是「一次性建图 → 保存 → 再也不改」。而是持续运行、持续更新。环境变了（家具移动了、门开了关了），地图自动更新。

关键机制：

  • 加载已有地图（/deserialize_map）
  • 正常建图运行（接收新激光帧）
  • 当发现旧地图与当前扫描不一致 → 标记旧节点为「需更新」
  • 下次优化时移除旧节点，用新数据替代
  • 周期性序列化保存（/serialize_map）

22.5 纯定位模式 (Localization) — 替代 AMCL

加载已有地图后，不更新地图，仅输出机器人当前在地图中的位姿。

ros2 launch slam_toolbox localization_launch.py \
  map_file_name:=/home/user/maps/my_map
维度AMCL（粒子滤波）slam_toolbox Localization
原理粒子滤波 + 似然域模型扫描匹配（与建图同款匹配器）
精度中（依赖粒子数量）高
全局定位优秀（不知道位置也能收敛）需初始值（需从 dock 或已知位置启动）

选型建议：如果机器人始终从已知位置启动（dock 充电桩），用 slam_toolbox Localization 精度更高。如果需要机器人「在任何位置启动后自己找位置」（kidnapped robot 问题），用 AMCL。

24.2 TF 树关系（最重要！）

正常运行时，TF 树必须满足如下链路（单根树，不能有闭环）：

map → odom → base_footprint → base_link → laser_link
  ↑          ↑                  ↑
  SLAM 发布   里程计发布          robot_state_publisher 发布

验证命令：

# 查看 odom→base_link 实时变换
ros2 run tf2_ros tf2_echo odom base_link
TF 链断裂的常见原因：
  1. 里程计没有发布 odom→base_footprint 的 TF
  2. robot_state_publisher 没有发布 base_link→laser_link 的静态 TF
  3. 帧名不匹配（URDF 里叫 laser，YAML 里写了 laser_link）

25.1 完整流程（6 步）

  1. 启动机器人：LiDAR + 里程计 + TF 正常发布，所有传感器话题有数据
  2. 启动 SLAM：用 Online Async 模式开始建图

25.3 建图关键注意事项

建图三大铁律：

  1. 走回环路径！不要让机器人只走一遍——回到起点附近、在已有区域多走几次。这能触发回环检测，是地图质量的决定性因素
  2. 速度别太快！建议 0.2-0.3 m/s。太快会导致扫描畸变（一帧扫描期间机器人移动了太多），匹配失败
  3. 多角度扫描同一区域！玻璃墙、镜面、细柱子——这些从单一角度难以正确建模，需要从多个方向扫描

25.4 地图加载导航的两种方案

方案 A：AMCL 定位 + Nav2 Planner

ros2 launch nav2_bringup navigation_launch.py \
  map:=/home/user/my_map.yaml

经典组合，适合大多数场景。AMCL 支持全局定位（任意起点启动）。

方案 B：slam_toolbox Localization + Nav2 Planner

ros2 launch slam_toolbox localization_launch.py \
  map_file_name:=/home/user/my_map
ros2 launch nav2_bringup navigation_launch.py \
  map:=/home/user/my_map.yaml

用 slam_toolbox 替代 AMCL 做定位，适合从已知起点启动的任务。定位精度高于 AMCL。

27. 故障排查手册

27.1 地图模糊 / 分层 / 重影 最常见问题

根因：里程计漂移严重，或回环检测没有成功触发。机器人「以为」自己走过的路径和真实路径偏差太大，导致同一堵墙被画到了不同的位置。

排查步骤：

  1. 检查里程计精度：让机器人直走 1 米，看 /odom 记录的距离是否接近 1 米。如果不准，校准轮径（wheel_radius_multiplier）
  2. 检查回环是否触发：看终端日志是否有 "Loop closure detected" 字样。如果没有，机器人可能没有回到过已建图区域
  3. 降低 loop_closure_search_radius 到 1.0，降低 loop_closure_min_response 到 0.2，让回环更容易触发
  4. 最重要的：多走回环路径！不要让机器人只走一遍——回到起点、在已有区域反复走
  5. 如果里程计实在太差：用 robot_localization 包融合 IMU 数据来改善

27.2 「No laser scan received」

根因：激光话题不匹配、激光没有发布数据、或 TF 树不完整。

逐项检查：

  1. ros2 topic echo /scan — 有数据吗？帧率正常吗（应该 ≥ 5Hz）？
  2. ros2 topic info /scan — 消息类型是 sensor_msgs/msg/LaserScan 吗？
  3. 配置文件中的 scan_topic 参数与实际话题名一致吗？
  4. ros2 run tf2_tools view_frames — 导出 TF 树 PDF，检查链是否从 odom 到 laser 完整
  5. ros2 run tf2_ros tf2_echo odom base_link — odom→base_link 变换存在并正常发布吗？
  6. 仿真模式下：use_sim_time 设为 true 了吗？Gazebo 在运行吗？

27.3 地图不更新或更新极慢

可能原因及解决：

  • 位姿图变得太大 → 使用 Async 模式（online_async_launch.py）
  • 分辨率太高 → 降低到 0.1
  • 全局优化耗时过长 → 降低 optimization_hz 到 1.0
  • 激光范围太大 → 减小 max_laser_range 到 8.0
  • 检查 /map 话题是否在发布：ros2 topic hz /map

27.4 地图保存后 Nav2 加载报错

常见原因：

  • .yaml 中的 image: 路径错了 — 必须使用绝对路径或正确的相对路径
  • 保存方式用混了：/serialize_map 存的是 .posegraph + .data 格式，Nav2 的 map_server 需要 .pgm + .yaml 格式。建图完成后要用 map_saver_cli 保存
  • free_thresh: 0.25 和 occupied_thresh: 0.65 必须与 map_server 期望匹配
  • negate: 0 对于 slam_toolbox 生成的地图通常是 0（不反转颜色）

27.5 回环检测误匹配（错误的回环）

现象：地图突然被「拉歪」——本不是一个地方的两个区域被强行拼到一起。这比没有回环还要糟糕。

解决：

  • 提高 loop_closure_min_response（如 0.4 或 0.5）——只有匹配得分很高的才认定是回环
  • 提高 loop_closure_min_response_fine ——精细验证门槛也要提高
  • 减小 loop_closure_search_radius ——只在更近的范围内搜索回环候选
  • 在长走廊等视觉高度相似的区域，上述参数应该更保守

27.6 TF 帧名不匹配 配置错误榜首

现象：slam_toolbox 启动后立即报错或地图位置完全不对。

诊断：

# 查看 TF 树中实际使用的帧名
ros2 run tf2_tools view_frames
# 对比 YAML 配置文件中的设置
# map_frame / odom_frame / base_frame 三者必须与 TF 树完全一致

常见错误：YAML 写 base_frame: base_link 但 TF 树中是 base_footprint（反之亦然）。差一个字符就失败——TF 帧名是大小写敏感的。

  1. 启动 Gazebo 仿真环境（一个有墙有障碍物的世界）
  2. 启动 slam_toolbox Online Async 模式
  3. 用键盘遥控机器人，低速走遍整个空间（务必走回环路径！）
  4. 在 RViz2 中观察地图的实时构建过程，理解每个参数的作用
  5. 用 map_saver_cli 保存地图
  6. 关闭 SLAM，用 Nav2 加载地图进行导航测试，验证地图质量

阶段三：读源码（理解原理的实现）

目标：理解 slam_toolbox 内部各模块是如何协同工作的。

  • lib/karto_sdk/src/ScanMatcher.cpp — 相关性扫描匹配的核心实现
  • src/pose_graph.cpp — 位姿图的数据结构和优化触发逻辑
  • src/solver_plugins/ceres_solver.cpp — 如何把位姿图转化为 Ceres 优化问题
  • src/loop_closure_assistant.cpp — 回环检测的策略和验证逻辑

阶段四：真实机器人部署

目标：在自己搭建的真实机器人上跑通建图→导航全流程。

  • 校准里程计（轮径标定，走 1m 对比 /odom 输出）
  • 如需要，配置 robot_localization 融合 IMU 提升里程计精度
  • 在真实环境中建图，注意地面材质（打滑）、光照、玻璃等因素的影响
  • 用 Lifelong 模式持续维护地图，适应环境变化

阶段五：进阶方向

SLAM 理论进阶

  • 读《Probabilistic Robotics》第 10-13 章（SLAM 经典教材）
  • 读 SPA 原始论文（Konolige et al., 2010）
  • 读 g2o 论文（Kummerle et al., 2011）
  • 了解 iSAM2 和 Bayes 树（Kaess et al., 2012）
  • 学习 SE(2)/SE(3) 李群李代数

工程进阶

  • 尝试 Cartographer 对比建图效果
  • 学习 3D LiDAR SLAM（LOAM、FAST-LIO2）
  • 学习视觉 SLAM（ORB-SLAM3）
  • 了解多机器人协作 SLAM
  • 了解语义 SLAM（融合物体识别信息）
