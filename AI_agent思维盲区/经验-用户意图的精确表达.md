# 通用经验：用户说"你描述得不对"时，不要换同义词，要先还原他的核心思想

## 这个模式长什么样

```
用户提出一个要求 / 一句原则
    ↓
agent 觉得"原句不够专业"
    ↓
用自己的技术框架把它抽象化、术语化
    ↓
用户："不是" "太蠢了" "意思还不是一样"
    ↓
agent 再换一版同义词
    ↓
用户继续否定
    ↓
agent 才开始问"我到底哪一维偏了"
```

这个循环的根因不是文笔差，而是 **agent 在改写时替换了用户的原意，而不是表达用户的原意**。

## 三类典型错误

### 1. 用抽象术语替换具体语义

用户原句：

> 有物体的地方就有碰撞，没有就没有

错误改写：

> 视觉、碰撞、感知三套模型不得对同一几何真值做出相互矛盾的表达

问题：把"物体—碰撞"这种**具体、可验证**的对应关系，替换成了"几何真值""无损表示"这类**抽象、无法直接验证**的说法。用户读到的是"你在用术语糊弄我"，而不是"你理解了我的意思"。

### 2. 把自己的技术栈塞进用户的需求

用户说的是仿真与物理世界的对应关系，agent 却把 LiDAR 感知、OctoMap、三套模型一致性强加进去。

问题：需求描述被扩大了。用户要的是 A，agent 写成了 A+B+C，即使 B、C 也对，也已经不是他的话。

### 3. 用等号/箭头堆叠关系

> 人眼看到的 = 物理引擎碰撞的 = LiDAR 射线能命中的

问题：等式只表达"相等"，丢失了**方向、条件、正例、反例**。真实需求是"有实体→碰撞，无实体→无碰撞"，是一个带条件的双向约束，不是一个值相等。

## 正确的改写流程

### 第 1 步：先复述，不加工

在动笔前，用一句话复述用户的核心思想，并确认它包含哪些要素：

| 要素 | 本例中的内容 |
|---|---|
| 对象 | 仿真环境中的碰撞建模 |
| 依据 | 现实物理世界的客观规律 |
| 正例 | 有实体几何结构的物体 → 产生真实碰撞响应 |
| 反例 | 空旷的非实体空间 → 不得产生非物理阻挡 |
| 结论 | 碰撞行为与真实空间占据情况严格对应 |

### 第 2 步：检查改写是否保真

改写后逐项对照：**对象、依据、正例、反例、结论**，五项必须全部保留，一项都不能被替换或删除。

### 第 3 步：只提升表达精度，不改变语义

可以做的：

- 补上"遵循现实世界的客观规律"这类依据
- 把"碰撞"细化为"碰撞响应（阻挡、反弹或受力）"
- 把"没有就没有"细化为"不得产生非物理的碰撞阻挡"
- 用"简而言之"收束成一句结论

不能做的：

- 换掉核心名词（实体 → 几何真值）
- 增加用户没提的维度（感知、雷达、建图）
- 把条件关系压成等号
- 为了"显得专业"而拉长句子或加抽象层级

### 第 4 步：连续被否定时，停止猜，改为诊断

如果连续 2～3 版都被否定，不要再改写，直接问清偏差维度：

- 是太抽象？
- 是重点偏了？
- 是多加了不该有的内容？
- 是结构不对（要一句话还是分点）？

本例中，前 3 版全错，问了一次"偏差在哪个方向"，用户一句话就说清了："我是说仿真应该和物理世界一样，有物体的地方就有碰撞，没有就没有。"

**用户往往不是不会表达，而是 agent 一直在错误的方向上改写。**

## 反例 vs 正例

### 反例

```
用户：仿真要和物理一样，所见即所得
agent：同一空间只能有一种几何真值……
用户：不是
agent：仿真必须复刻真实物理世界……
用户：不是!
agent：视觉模型、碰撞模型、雷达可达边界三者严格重合……
用户：操你妈的，你老是模仿我的说法
```

### 正例

```
用户：仿真要和物理一样，有物体的地方就有碰撞，没有就没有
agent：（先还原五要素）
      对象：仿真碰撞建模
      依据：现实物理世界规律
      正例：有实体 → 真实碰撞响应
      反例：空旷空间 → 无非物理阻挡
      结论：碰撞与空间占据严格对应
agent：在 Gazebo 仿真环境中，物理碰撞的建模应当遵循现实世界的客观规律：
      存在实体几何结构的物体之间应当产生真实的碰撞响应；
      空旷的非实体空间则不应产生任何非物理的碰撞阻挡。
      简而言之，仿真中的碰撞行为应与真实物理世界的空间占据情况严格对应。
用户：这才是我想要的
```

## 记住这一点

**改写需求时，agent 的任务是"把用户说不清的话说清楚"，不是"把用户的话换成 agent 自己的话"。**

判断标准只有一条：用户读完，能不能指着其中任何一句说"这不是我的意思"。能指出来，就是改写失败；指不出来，才算表达成功。
