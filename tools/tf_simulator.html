常见问题

odom 不是里程表数字吗？为什么是坐标系？
ROS 中的 odom 是 odometry 的缩写，不只是「跑了多少公里」。

汽车的里程表只累计距离，丢了方向信息。但机器人的里程计需要知道「走了多远 + 朝向哪里」—— 它通过对轮子转了多少圈（编码器数据）不断积分，算出机器人当前的 (x, y, yaw)。

所以 odom → base_footprint 变换 = 机器人相对开机起点的位置和朝向。这是一个完整位姿，不是单独一个数字。

odom 坐标系原点 = 开机那一刻机器人的位置，机器人动，这个变换就跟着变。
map → odom 是什么？为什么需要它？
odom → base_footprint 是靠轮子编码器算出来的，会随时间累积误差（打滑、不平路面 → 漂移）。

AMCL 用激光雷达扫描 + 已知地图来修正这个漂移，修正量就是 map → odom 变换。

所以 map → base_footprint = map → odom + odom → base_footprint 才是机器人在世界中的真实位姿。
变换中的旋转是相对于哪个轴？
ROS 坐标系标准：
• X 轴 = 机器人前方
• Y 轴 = 机器人左侧
• Z 轴 = 上方

Roll = 绕 X 轴旋转（侧翻）
Pitch = 绕 Y 轴旋转（俯仰）
Yaw = 绕 Z 轴旋转（转向，地面机器人最常用）
父坐标系变动，子坐标系会跟着动吗？
会。TF 树中任何坐标系都是相对于父坐标系定义的。

例如 map → odom → base_footprint → laser_sensor：
• 机器人移动 → odom→base_footprint 变化 → laser_sensor 在 map 中的位置自动更新
• AMCL 修正 → map→odom 变化 → 整条链全部跟着动

这就是 rviz 中机器人模型能实时跟随移动的原因。
