URDF · ROS 入门图解

机器人的 joint 关节
到底是个什么东西？

在 URDF 里，joint 不是一个零件，而是一段「关系」。它没有重量、没有形状，却决定了机器人怎么动。下面我们用生活比喻 + 可交互的动画，把它彻底讲清楚。

1先从生活里找对应

不用想机器人，先看看身边这些东西——它们就是四种最常用的 joint。

门铰链

门只能转一定角度
revolute

抽屉滑轨

只能来回推拉
prismatic

焊死的铁管

完全不能动
fixed

旋转门 / 风车

能无限转圈
continuous
关键直觉：铰链、滑轨本身都不是「门」或「抽屉」，它们只是让两个东西以特定方式相对运动的那层关系。URDF 里的 joint 就是这个角色。

2那 joint 到底是什么

一句话：它是连接两根「骨头」的「关节囊」——本身没重量，但规定了骨头怎么动。

在 URDF 里，整个机器人被拆成两部分：

link — 刚体（具体的）

一根骨头、一截外壳、一个轮子。它有 mass（质量）、inertia（惯性）、visual（外观）、collision（碰撞体）。

→ 描述「这是一块什么样的东西」

joint — 运动关系（抽象的）

两块骨头之间「能怎么动」。它没有质量、没有惯性，只携带 type（动法）、axis（沿/绕哪个轴）、limit（范围）。

→ 描述「这两块东西之间是什么关系」

把它们串起来，就成一棵树：

注意紫色的 joint 节点：它是树上的「边」，不是「叶子」。它不装任何材料，只描述两端怎么连、怎么动。

3动手玩一玩

选一种 joint 类型，看一根杆子（child link）相对底座（parent link）会怎么动。拖动滑块还能亲手控制它。

axis 运动轴
revolute 绕 z 轴旋转（垂直屏幕，指向你）。圆点中的小白点就是这根轴的"端面"。
revolute（旋转关节）：杆子绕 joint 转动，角度被 limit 限制在 ±90°。紫色扇形就是它能到达的范围。现实中对应一个带限位的伺服电机，比如机械臂的肩关节。

对应的 URDF 写法会跟着你的选择实时变化：

<joint name="shoulder" type="revolute">
  <parent link="base_link"/>
  <child  link="upper_link"/>
  <origin xyz="0 0 0.1" rpy="0 0 0"/>
  <axis   xyz="0 0 1"/>          <!-- 绕 Z 轴 -->
  <limit  lower="-1.57" upper="1.57" effort="10" velocity="1.0"/>
  <!-- 当前角度 0° ≈ 0.00 rad -->
</joint>

4joint 身上带了什么

一个 joint 实际只携带这几样东西——记住它们，就掌握了 joint 的全部。

属性含义例子
type运动类型（怎么动）revolute
originparent 坐标系 → joint 坐标系的刚体变换（位置+姿态）xyz="0 0 0.1" rpy="0 0 0"
axis运动沿着/绕着哪个轴xyz="0 0 1"（绕 Z 轴）
limit角度/位移的上下限、最大速度、最大力lower="-1.57" upper="1.57"
dynamics阻尼、静摩擦（可选，仿真用）damping="0.5" friction="0.1"
mimic让本关节跟随另一个关节运动（齿轮联动）joint="gripper" multiplier="2"
注意：这里面没有任何关于「质量」的字段。质量、惯性、外观、碰撞——全部挂在两端的 link 上。joint 只管「关系」，不管「材料」。这就是它「抽象」的根源。

5看一个完整的 URDF

两根杆、一个旋转关节，最小可运行的机械臂。注意 link 和 joint 是怎么交替出现的。

<!-- ① 第一根杆：底座，有质量和惯性 -->
<link name="base_link">
  <inertial>
    <mass value="1.0"/>
    <inertia ixx="0.01" iyy="0.01" izz="0.01"/>
  </inertial>
</link>

<!-- ② 关节：把第二根杆连到底座上，绕 Z 轴转 ±90° -->
<joint name="shoulder" type="revolute">
  <parent link="base_link"/>
  <child  link="upper_link"/>
  <origin xyz="0 0 0.1" rpy="0 0 0"/>   <!-- joint 在底座上方 0.1m 处 -->
  <axis   xyz="0 0 1"/>              <!-- 绕 Z 轴旋转 -->
  <limit  lower="-1.57" upper="1.57" effort="10" velocity="1.0"/>
</joint>

<!-- ③ 第二根杆：被这个关节驱动的 child -->
<link name="upper_link">
  <inertial>
    <mass value="0.5"/>
    <inertia ixx="0.005" iyy="0.005" izz="0.005"/>
  </inertial>
</link>

读法：先有一个 link（底座），再用一个 joint 把第二根 link「挂」上去，并规定它绕 Z 轴在 ±90° 内转。joint 的 parent/child 指向的是 link 的名字——它本身不占体积，只是把两个名字用一条「运动规则」连起来。

6抽象，但不虚构

joint 没有质量，却能在现实中被找到、被驱动——因为它对应真实的执行器。

URDF 里的 joint
一段 XML 文本
名字：shoulder
无质量、无形状
⇄
真实硬件
一台伺服电机
装在底座顶部
有编码器反馈角度

在 ROS 里，控制器（比如 ros2_control 的 JointTrajectoryController）正是以 joint 的名字为索引去下达指令、读取反馈的：

# 给名为 "shoulder" 的 joint 下达 30° 的目标
joint_names: ["shoulder"]
points:
  - positions: [0.52]    # 30° ≈ 0.52 rad
    time_from_start: { sec: 2 }

所以 joint 在「运动学描述」这一层是抽象的，在「控制接口」这一层又是具体可寻址的——你告诉系统「让 shoulder 转到 30°」，系统就知道去驱动哪台电机。这就是它「抽象但不虚构」的精妙之处。

7它有一个硬限制

URDF 的 joint 只能描述「树」，不能描述「环」。

因为每个 child link 只能有一个 parent，joint 拼出来的永远是一棵有向树。这意味着：

✓ 能描述

串/并联机械臂、差速底盘、人形机器人的开链肢体——只要没有「环」就行。

✗ 不能描述

四连杆机构、Delta 并联机器人、Stewart 平台——它们有闭环，某个 link 会被两个 joint 指向。

遇到闭环怎么办？改用 SDF 格式（它原生支持闭环），或者在 URDF 里用 mimic 关节近似模拟从动关系。这是 URDF 设计时为「简单」付出的代价。

8三句话记住它

如果只记三点，就记这些。

01
是「关系」不是「零件」
joint 描述两个 link 怎么相对运动，本身无质量、无惯性、无形状。
02
只带 5 样东西
type 怎么动、origin 在哪、axis 沿哪个轴、limit 限位、dynamics 阻尼摩擦。
03
抽象但可寻址
它在运动学里抽象，却对应真实电机，控制器能按名字直接驱动它。

回到最初的问题：joint 是抽象概念吗？
是的——但它是「有现实对应物」的抽象，是连接数学模型与真实电机的桥梁。
